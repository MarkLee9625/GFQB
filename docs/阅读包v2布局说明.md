# 阅读包 v2 数据布局说明

> 落地日期：2026-10-20（R1-b/R3）｜状态：生产模板默认导出 v2，降级骨架保留 v1
> 背景与基线见 `开发方案-阅读包体积与打开速度优化.md` 与 `_体积分析/R0-基线报告-2026第3期.md`

## 1. 为什么是 v2

v1 把整包 JSON（含内层 base64 媒体）gzip 后再整体 base64：打开即克隆/解压/解析
200MB+（第3期口径），首屏慢、内存峰值 GB 级。v2 把"索引 + 按篇分块 + 媒体单编码"
一次做对：首屏只碰 KB 级 meta + 首篇 body，后台流式索引其余。

体积结论（实测）：v2 与 v1 基本持平（±2MB）——对已压缩媒体，gzip 整包与媒体单编码
恰好打平（见 R0 报告 §4）。**v2 省的是打开速度与内存，不是体积**（体积靠 R-D0/R4）。

## 2. 布局

注入变量（`reader.ts injectV2DataIntoReader`，锚点 `<!--SWS_READER_DATA-->`）：

| 变量 | 内容 |
|---|---|
| `__SWS_FORMAT__` | `'v2'`（缺席即 v1 老文件） |
| `__SWS_V2_METHOD__` | `gzip`（与 `__SWS_COMPRESSION_METHOD__` 同值） |
| `__SWS_V2_META_B64__` | 外壳数组 gzip+base64（id/标题/分类/排序/标签/摘要/hasPdf，KB 级） |
| `__SWS_V2_BODIES_B64__` | 每篇一包（媒体抽走换 token），各 gzip+base64，下标与 meta 对齐 |
| `__SWS_V2_MEDIA__` | `mime,b64` 数组，全局去重，**不 gzip**（已压缩媒体压不动，省 CPU） |
| `__SWS_DATA_CONFIG_B64__` | 配置包（与 v1 同） |

Token：`__SWS_M2_{n}__`（n = 媒体表下标）。构建期做 JSON 文本级正则替换
（cover/正文/blocks/pdf 全覆盖）；原文若已含完整 token 形态直接抛错拒绝导出
（裸前缀文本放行——回填正则只认完整形态）。
pdfData 裸 base64 先归一为 data URI（阅读器双兼容）。

## 3. 读写链路

- 导出：`reader.ts` 先看模板 → 有模板走 v2（`reader.worker.ts` 内解析→分块→压缩→拼注入脚本，
  主线程只做一次模板替换，零大对象）→ 注入；无模板走 v1（`buildReaderHTML` 降级骨架，老链路保留演练）。
- 阅读（React 模板）：`embeddedData.ts`（`readV2Store`/`parseV2Meta`/`createV2BodyLoader`）
  → `reader.tsx` 外壳先行、首篇优先、后台顺序索引；翻页按需解码（在途去重）。
  检索：外壳字段恒可搜，正文搜已解码缓存（索引完成后即全量）。
  失败处理：单篇失败记 `failedIds`，侧边栏常驻"检索不全 + 重试"，正文窗可单篇重试；
  索引干净完成即释放媒体表（有失败则保留供重试）。
  内存：单篇缓存成功即清空其 b64（失败保留）；下标/id 错位即抛响亮错。
- 兼容：v1 文件无 v2 标记，`reader.tsx` 走原整包路径（代码原样保留）。

## 4. 关键文件

- `src/services/export/reader.worker.ts`（v1/v2 双分支）、`reader.ts`（选型+注入）
- `src/utils/embeddedData.ts`（v2 loader）+ 测试、`reader.tsx`（骨架优先 UI）
- 验证：`npm run verify:v2e2e`（新模板 + 真实 27 篇 → headless 打开断言 + v1 兼容）

## 5. 已知边界

- 外壳顺序即导出排序，不二次排序（保下标对齐）。
- R-D0 先行：有 content 即剥离 blocks（阅读器回退重算）；空 content 保 blocks。
- 单文件文本约束下媒体下限为 1.33×二进制；再省体积只能降画质或外置媒体。
