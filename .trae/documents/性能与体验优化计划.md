# 性能与用户体验优化计划

## 审查结论

第三轮代码审查未发现 Bug，但从**性能**和**用户体验**角度，存在以下可优化项。按影响程度分为 P0（显著改善）和 P1（锦上添花）。

---

## P0：显著改善体验的优化

### 1. 切换文章时滚动位置不重置

**问题**：用户在阅读长文章时滚动到底部，切换到下一篇文章后仍然停留在底部，需要手动滚回顶部。这是阅读体验中最明显的痛点。

**方案**：在 `handleSelectArticle` 中，切换文章后调用内容区滚动容器 `scrollTop = 0`。

**修改文件**：`App.tsx`
- 给 MainLayout 的内容区容器添加 ref
- 在 `handleSelectArticle` 中切换文章后重置滚动位置

---

### 2. PaperView 缺少 React.memo 导致频繁重渲染

**问题**：PaperView 是一个近 900 行的大型组件，包含封面/封底/正文三种渲染路径。由于父组件 AppContent 的任何状态变化（如 `isEditorOpen`、`isCatManagerOpen`、`searchQuery` 等）都会导致 PaperView 重新执行整个函数体，即使 `article`、`logo`、`isEditMode` 等实际使用的 props 并未变化。

**影响**：在拖拽封面图片时，`zoom` 状态频繁更新会触发 PaperView 重渲染；编辑器打开/关闭、搜索输入等操作也会导致 PaperView 不必要的重渲染。

**方案**：用 `React.memo` 包裹 PaperView，仅在相关 props 变化时重渲染。

**修改文件**：`components/PaperView.tsx`
- 将 `export const PaperView` 改为 `React.memo` 包裹
- 注意：`onUpdate`、`onImageUpload`、`onNext` 等回调需要确保引用稳定（已在 App.tsx 中通过 ref 模式或 useCallback 处理）

---

### 3. Editor 接收不稳定的 article prop 引用

**问题**：App.tsx 第 823 行：
```tsx
article={currentId ? (articles.find(a => a.id === currentId) || {}) : {}}
```
`articles.find()` 每次返回新引用，空对象 `{}` 每次也是新引用。这意味着即使文章内容没变，Editor 也会因引用变化而重渲染。结合 Editor 是一个 1300+ 行的组件，这个开销不可忽视。

**方案**：用 `useMemo` 缓存 article 对象引用，仅在 currentId 或 articles 真正变化时才更新。

**修改文件**：`App.tsx`
- 将 `currentArticle` 的计算改为 `useMemo`
- 将传给 Editor 的 article prop 使用 `useMemo` 稳定引用

---

### 4. CSS 样式在每次渲染时重复注入 DOM

**问题**：Editor 和 PaperView 都有 `<style>{CONSTANTS.UNIFIED_STYLES}</style>`，这意味着每次组件渲染都会向 DOM 插入一个 `<style>` 标签。React 在 diff 时会复用该标签，但首次渲染和组件重新挂载时会重复插入。

**方案**：将 `UNIFIED_STYLES` 提升为全局样式，在应用入口（index.css 或 App 组件）一次性注入，Editor 和 PaperView 中移除 `<style>` 标签。

**修改文件**：
- `types.ts` 或 `index.css`：将 UNIFIED_STYLES 内容迁移到全局 CSS
- `components/Editor.tsx`：移除 `<style>{CONSTANTS.UNIFIED_STYLES}</style>`
- `components/PaperView.tsx`：移除 `<style>{CONSTANTS.UNIFIED_STYLES}</style>`

## P1：锦上添花的优化

### 5. Editor 保存操作缺少视觉反馈

**问题**：用户在编辑器中按 Ctrl+S 保存时，没有任何视觉反馈（如 toast 提示"已保存"），用户不确定操作是否成功。虽然保存后编辑器会关闭，但对于 Ctrl+S 这种用户期望"保存但继续编辑"的操作，缺少反馈会造成焦虑。

**方案**：在 Editor 的 Ctrl+S 处理中，保存后显示一个短暂的 toast 提示，而不是直接关闭编辑器。

**修改文件**：`components/Editor.tsx`
- Ctrl+S 保存后显示 toast 提示"已自动保存"，不关闭编辑器
- 或者：保存后短暂显示成功状态，1.5秒后自动关闭

---

### 6. 图片压缩设置每次打开编辑器都重置

**问题**：Editor 中的图片压缩设置（格式、质量、最大宽度）是组件本地 state，每次关闭再打开编辑器都会重置为默认值。对于有特定压缩偏好的用户，需要反复调整。

**方案**：将压缩设置持久化到 localStorage，编辑器初始化时读取。

**修改文件**：`components/Editor.tsx`
- 压缩设置的初始值从 localStorage 读取
- 设置变化时同步写入 localStorage

---

### 7. DesignToggle 组件在 PaperView 内部定义

**问题**：`DesignToggle` 在 PaperView 函数体内定义（第 286 行），每次渲染都会创建新的组件定义。React 在 diff 时会认为是不同组件，导致卸载旧组件、挂载新组件，产生不必要的 DOM 操作。

**方案**：将 DesignToggle 提取到 PaperView 外部，通过 props 传递所需数据。

**修改文件**：`components/PaperView.tsx`
- 将 DesignToggle 移到 PaperView 外部
- 通过 props 传入 `isEditMode`、`useAlternateDesign`、`setUseAlternateDesign`

---

## 实施优先级

| 序号 | 优化项 | 类型 | 影响 | 复杂度 |
|------|--------|------|------|--------|
| 1 | 切换文章滚动重置 | UX | ★★★★★ | 低 |
| 2 | PaperView React.memo | 性能 | ★★★★ | 低 |
| 3 | Editor article prop 稳定引用 | 性能 | ★★★★ | 低 |
| 4 | CSS 全局注入 | 性能 | ★★★ | 中 |
| 5 | Editor 保存反馈 | UX | ★★★ | 低 |
| 6 | 压缩设置持久化 | UX | ★★ | 低 |
| 7 | DesignToggle 提取 | 性能 | ★★ | 低 |

## 约束

- 所有优化**不改变任何原有功能和 UI 外观**
- 仅改善性能和交互体验
- 优化后需通过 `npx vite build` 验证
