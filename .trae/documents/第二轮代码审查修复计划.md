## 🔴 上一轮修复引入的新问题

### 1. App.tsx — handleExportRef 在函数声明前使用

* **文件**: [App.tsx](file:///c:/Users/k1073/OneDrive%20-%20stu.just.edu.cn/%E5%89%8D%E7%AB%AF%E9%A1%B9%E7%9B%AE/%E5%B7%A5%E6%B3%95%E6%83%85%E6%8A%A5%E6%94%B6%E9%9B%86%E7%B3%BB%E7%BB%9F/%E5%B7%A5%E6%B3%95%E6%83%85%E6%8A%A5%E7%BC%96%E8%BE%91%E5%99%A8/App.tsx#L234-L241)

* **问题**: `handleExportRef`、`toggleReadingModeRef`、`handleDeleteRef`、`handleNavigateRef` 这四个 ref 在第234-241行赋值，但它们引用的函数（`handleExport`、`toggleReadingMode`、`handleDelete`、`handleNavigate`）在第374行、第535行、第704行才声明。由于 JavaScript 的函数声明提升（hoisting）只对 `function` 声明有效，而这些函数是用 `const` 声明的箭头函数，**不存在提升**。这意味着在组件首次渲染时，第234-241行的 `.current = handleExport` 等赋值会引用 `undefined`。

* **影响**: 首次渲染时按快捷键会调用 `undefined` 导致崩溃

* **修复**: 将 ref 赋值移到函数声明之后，或改用 `function` 声明

### 2. App.tsx — handleImport 中仍残留 escape() 调用

* **文件**: [App.tsx](file:///c:/Users/k1073/OneDrive%20-%20stu.just.edu.cn/%E5%89%8D%E7%AB%AF%E9%A1%B9%E7%9B%AE/%E5%B7%A5%E6%B3%95%E6%83%85%E6%8A%A5%E6%94%B6%E9%9B%86%E7%B3%BB%E7%BB%9F/%E5%B7%A5%E6%B3%95%E6%83%85%E6%8A%A5%E7%BC%96%E8%BE%91%E5%99%A8/App.tsx#L587-L592)

* **问题**: 上一轮修复只替换了嵌入式 Reader 数据的 `decodeB64Utf8`，但 `handleImport` 中从 HTML 导入时的两处 `decodeURIComponent(escape(atob(...)))` 仍然使用已弃用的 `escape()` 函数。

* **影响**: 从 HTML 导出文件导入含中文数据时可能解码失败

* **修复**: 替换为 `decodeB64Utf8`

### 3. PaperView\.tsx — handleMouseUp 使用了过期的 zoom 状态

* **文件**: [PaperView.tsx](file:///c:/Users/k1073/OneDrive%20-%20stu.just.edu.cn/%E5%89%8D%E7%AB%AF%E9%A1%B9%E7%9B%AE/%E5%B7%A5%E6%B3%95%E6%83%85%E6%8A%A5%E6%94%B6%E9%9B%86%E7%B3%BB%E7%BB%9F/%E5%B7%A5%E6%B3%95%E6%83%85%E6%8A%A5%E7%BC%96%E8%BE%91%E5%99%A8/components/PaperView.tsx#L274-L281)

* **问题**: `handleMouseUp`（第274行）直接读取 `zoom.x` 和 `zoom.y`，但 `handleMouseMove` 中通过 `setZoom(prev => ...)` 更新 zoom，这是异步的。在快速拖拽时，`handleMouseUp` 可能读取到旧的 zoom 值，导致保存的位置偏移。而全局 `mouseup` 事件处理器已经使用 `zoomRef.current` 修复了这个问题，但组件内的 `handleMouseUp` 没有同步修复。

* **影响**: 拖拽封面/封底图片后，位置保存可能偏移

* **修复**: `handleMouseUp` 也使用 `zoomRef.current`

### 4. Editor.tsx — prevArticleIdRef 在编辑器关闭时重置为 null，但未清理 contentRef

* **文件**: [Editor.tsx](file:///c:/Users/k1073/OneDrive%20-%20stu.just.edu.cn/%E5%89%8D%E7%AB%AF%E9%A1%B9%E7%9B%AE/%E5%B7%A5%E6%B3%95%E6%83%85%E6%8A%A5%E6%94%B6%E9%9B%86%E7%B3%BB%E7%BB%9F/%E5%B7%A5%E6%B3%95%E6%83%85%E6%8A%A5%E7%BC%96%E8%BE%91%E5%99%A8/components/Editor.tsx#L115-L119)

* **问题**: 上一轮修复将 innerHTML 重置逻辑改为仅在文章 ID 变化时触发，但关闭编辑器时 `prevArticleIdRef.current = null`，下次打开同一篇文章时 ID 没变（还是同一个），不会重置 innerHTML。这在"关闭编辑器再打开同一篇文章"的场景下，编辑器内容不会被刷新，可能显示过期的 DOM 状态。

* **影响**: 关闭再打开同一篇文章时，编辑器可能显示旧内容

* **修复**: 关闭时不重置 `prevArticleIdRef`，或在 `isOpen` 从 false 变为 true 时也触发重置

## 🟡 遗漏的隐藏Bug

### 5. App.tsx — handleReset 中 ID 生成方式与 useJournal 不一致

* **文件**: [App.tsx](file:///c:/Users/k1073/OneDrive%20-%20stu.just.edu.cn/%E5%89%8D%E7%AB%AF%E9%A1%B9%E7%9B%AE/%E5%B7%A5%E6%B3%95%E6%83%85%E6%8A%A5%E6%94%B6%E9%9B%86%E7%B3%BB%E7%BB%9F/%E5%B7%A5%E6%B3%95%E6%83%85%E6%8A%A5%E7%BC%96%E8%BE%91%E5%99%A8/App.tsx#L362-L371)

* **问题**: `handleReset` 使用 `Date.now()` 和 `Date.now() + 1` 生成 ID，没有使用 `Math.random()` 增强唯一性（与 useJournal 的 createArticle 不一致）。

* **影响**: 低风险，但与 createArticle 的 ID 策略不一致

* **修复**: 使用 `Date.now() + Math.floor(Math.random() * 1000)` 保持一致

### 6. App.tsx — useEffect 保存 logo/sidebarMeta 缺少 db 状态检查

* **文件**: [App.tsx](file:///c:/Users/k1073/OneDrive%20-%20stu.just.edu.cn/%E5%89%8D%E7%AB%AF%E9%A1%B9%E7%9B%AE/%E5%B7%A5%E6%B3%95%E6%83%85%E6%8A%A5%E6%94%B6%E9%9B%86%E7%B3%BB%E7%BB%9F/%E5%B7%A5%E6%B3%95%E6%83%85%E6%8A%A5%E7%BC%96%E8%BE%91%E5%99%A8/App.tsx#L329-L331)

* **问题**: `useEffect` 中 `if (!loading) db.save(...)` 在 loading 变为 false 时触发，但此时 db 可能尚未完成初始化（useJournal 的 `load` 函数中 `await db.init()` 是异步的，loading 在 init 完成后才设为 false，所以理论上安全）。但如果 db.init 失败，loading 仍会变为 false（finally 块中），此时 db.save 会静默失败。

* **影响**: db 初始化失败时配置数据无法保存，且无错误提示

* **修复**: 添加 try-catch 包裹 db.save 调用

### 7. Editor.tsx — handleFile 中 setTimeout 50ms 内如果组件卸载会报错

* **文件**: [Editor.tsx](file:///c:/Users/k1073/OneDrive%20-%20stu.just.edu.cn/%E5%89%8D%E7%AB%AF%E9%A1%B9%E7%9B%AE/%E5%B7%A5%E6%B3%95%E6%83%85%E6%8A%A5%E6%94%B6%E9%9B%86%E7%B3%BB%E7%BB%9F/%E5%B7%A5%E6%B3%95%E6%83%85%E6%8A%A5%E7%BC%96%E8%BE%91%E5%99%A8/components/Editor.tsx#L654-L758)

* **问题**: `handleFile` 使用 `window.setTimeout(async () => { ... }, 50)` 延迟执行文件处理。如果用户在 50ms 内关闭编辑器，异步回调仍会执行，此时 `contentRef.current` 可能为 null，导致 `insertHtml` 等函数崩溃。虽然有 `timeoutIdsRef` 清理机制，但 `clearTimeout` 只能阻止回调启动，不能阻止已启动的异步操作。

* **影响**: 快速关闭编辑器时可能报错

* **修复**: 在异步回调开始时检查 `contentRef.current` 是否存在

### 8. PaperView\.tsx — useBlobUrl 的 useEffect 依赖 blobUrl 可能导致循环

* **文件**: [PaperView.tsx](file:///c:/Users/k1073/OneDrive%20-%20stu.just.edu.cn/%E5%89%8D%E7%AB%AF%E9%A1%B9%E7%9B%AE/%E5%B7%A5%E6%B3%95%E6%83%85%E6%8A%A5%E6%94%B6%E9%9B%86%E7%B3%BB%E7%BB%9F/%E5%B7%A5%E6%B3%95%E6%83%85%E6%8A%A5%E7%BC%96%E8%BE%91%E5%99%A8/components/PaperView.tsx#L31-L40)

* **问题**: `useBlobUrl` 的 useEffect 依赖 `[dataUrl, blobManager, blobUrl]`，其中 `blobUrl` 是该 useEffect 自己通过 `setBlobUrl` 设置的。当 `dataUrl` 变化时，渲染期间的同步更新已经设置了 `blobUrl`，然后 useEffect 又因为 `blobUrl` 变化而触发，执行 `blobManager.getBlobUrl(dataUrl)` 获取同一个 URL，发现 `currentUrl !== blobUrl` 为 false，所以不会再次设置。虽然不会导致无限循环，但 useEffect 会在每次 dataUrl 变化时多执行一次无用的比较。

* **影响**: 轻微性能浪费

* **修复**: 从 useEffect 依赖中移除 `blobUrl`，仅依赖 `dataUrl`

### 9. useJournal.ts — createArticle 的 articles 依赖导致回调不稳定

* **文件**: [useJournal.ts](file:///c:/Users/k1073/OneDrive%20-%20stu.just.edu.cn/%E5%89%8D%E7%AB%AF%E9%A1%B9%E7%9B%AE/%E5%B7%A5%E6%B3%95%E6%83%85%E6%8A%A5%E6%94%B6%E9%9B%86%E7%B3%BB%E7%BB%9F/%E5%B7%A5%E6%B3%95%E6%83%85%E6%8A%A5%E7%BC%96%E8%BE%91%E5%99%A8/hooks/useJournal.ts#L127-L153)

* **问题**: `createArticle` 的 `useCallback` 依赖 `[articles, enforceOrder]`，其中 `articles` 在每次更新时都会变化，导致 `createArticle` 频繁重建。这会影响所有依赖 `createArticle` 的组件（如 App.tsx 的 `handleAdoptArticle`）。

* **影响**: 性能浪费，但不影响功能

* **修复**: 使用 `useRef` 存储 articles 的最新值，将 articles 从依赖中移除

### 10. Editor.tsx — 编辑器关闭时 objectUrlsRef 被清理两次

* **问题**: `objectUrlsRef.current` 在两个地方被清理：① useEffect 中 `isOpen` 为 false 时（第117行），② 键盘事件 useEffect 的 cleanup 中（第273行）。当编辑器关闭时，两个清理逻辑都会执行，第二次清理时数组已经为空，虽然不会报错，但逻辑冗余。
